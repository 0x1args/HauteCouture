## Domain-Driven Design aka DDD

The entire system is built on the Domain-Driven Design methodology. All defined subdomains, as the problem space, map to their corresponding bounded contexts as the solution space (i.e., one-to-one). Bounded contexts directly define the boundaries for the microservices architecture, meaning one context = 1 microservice. The strategic design part is available as the Domain Knowledge Base. The tactical design part contains the description within each corresponding microservice.

**Reference documentation (Domain Knowledge Base):** https://github.com/0x1args/HauteCouture/tree/main/docs/domain-driven-design.md
